# ClassPro HSK3 第14课及后续课程建设工作规范

> 文档状态：现行（Active）
> 版本：v1.1
> 生效日期：2026-10-30
> 适用范围：HSK3-L14 及后续从零建设、旧课升级与公共“用”机制接入
> 目的：把已经在 L9—L13 验证的课程框架固化为唯一建设基线，避免再次回退到 L8 或更早的旧模板。

---

## 1. 这份规范解决什么问题

L13 从零建设时经历了多次返工。首版沿用了 L8 的模板和呈现方式；补充 L9—L12 材料后，仍然没有一次进入当前框架，直到第三轮调整才达到预期。

这不是单个内容设计错误，而是建设流程存在以下系统性缺口：

1. **没有唯一权威基线。** 最新机制分散在 L9—L12 配置、共享运行时、校验脚本和对话记录中，仓库内没有一份明确声明“当前应按什么建设”的现行文档。
2. **旧文档仍具有误导性。** `HSK3界面模板与执行标准.md` 仍将 L01 写为后续课程默认模板，旧的课程方案也保留早期数据结构。执行者无法判断新旧规则的优先级。
3. **共享文件名称造成锚定偏差。** 公共“用”页面仍叫 `l08-use-pilot.html/js`。这是历史文件名，不代表 L8 是课程内容或教学样式模板，但名称容易让执行者把“共享运行时”误解为“复制 L8”。
4. **“参考 L9—L12”不够精确。** 四课各有课程专属样式，只有部分机制是公共的。把四课笼统交给执行者，容易发生选择性模仿和结构混用。
5. **“正式课程建设”和“用机制接入”被割裂。** 如果先按旧结构完成正式课，再在最后接“用”，会造成语法、课文、练习和资源 ID 无法自然映射，只能返工补结构。
6. **验收标准只有文字，没有前置闸门。** 旧版结构即使能够打开页面，也不会在内容设计阶段失败，问题通常到人工体验时才被发现。
7. **缺少禁止项。** 提示词说明了“要做什么”，却没有明确列出不得出现的旧结构、旧页面和课程专用分支。

因此，今后不能只靠一段长提示词控制结果，而要使用：

**版本化基线 + 分阶段交付 + 每阶段停止确认 + 自动校验 + 人工体验**。

## 2. 权威规则与优先级

发生冲突时，按以下顺序处理：

| 优先级 | 权威来源 | 用途 |
|---|---|---|
| 1 | 本文档 | 决定建设流程、公共机制边界、硬性禁止项和验收闸门 |
| 2 | 当前已上线并已提交的最新完整课程 | 提供实际可运行的结构基线；L13 正式上线并合并后，L14 默认以 L13 为首要基线 |
| 3 | `classpro-hsk3-lesson` 课程建设技能 | 约束具体执行步骤、课程数据质量和浏览器验收 |
| 4 | `classpro-use-profile/v3`、共享运行时及对应校验脚本 | 定义公共“用”、统一学生端、证据、计时器和路由能力 |
| 5 | 当课冻结版结构化清单 | 定义该课专属任务、词汇、语法、课文、练习和资源映射 |
| 6 | L8—L12 旧方案、旧审计文档和历史对话 | 只作历史参考，不得覆盖现行规则 |

### 2.1 找不到基线时的处理

开始新课前，必须在当前分支中确认“最新完整课程”的正式 JSON、构建脚本、校验脚本、升级配置和课程目录状态均存在。

如果 L13 已经上线，但当前工作区或分支中没有 L13：

- 停止课程设计和编码；
- 先说明当前分支落后或工作区不完整；
- 获取正确分支或最新提交；
- 不得静默退回 L12、L8 或 L01 作为模板。

### 2.2 关于 `l08-use-pilot.*`

`source/in-class/l08-use-pilot.html` 和 `source/in-class/l08-use-pilot.js` 是历史命名的**公共运行时**。

- 可以复用其公共能力；
- 不得把其 L8 内容、页面布局细节或课程教学样式当作新课模板；
- 不因新建 L14 而复制 `l14-use.html/js`；
- 不加入 `lesson === "HSK3-L14"` 一类课程专用运行时分支。

## 3. 当前公共框架：必须统一的部分

以下是平台公共机制，不随课程改变。

### 3.1 教师主界面

主界面保持五个入口：

1. 应用
2. 讲授
3. 练习
4. 竞赛
5. 测试

“应用”由共享升级入口注入；正式教师页不得为某一课另造专属“用”页面。

### 3.2 MINI 循环

默认一篇课文对应一个 MINI 循环。若教材实际不是四篇课文，必须先提出差异，不得机械制造四个循环。

每个循环遵循：

`起点表达 → 教师按需调用资源 → 终点表达`

“用”是表达起点和终点，不强迫所有课采用完全相同的内部教学流程。

### 3.3 三类核心证据

只统一记录：

1. `entry_expression`：起点表达；
2. `actual_learning_path`：教师在本 MINI 中实际打开的课堂资源；
3. `exit_expression`：终点表达。

不默认增加逐学生资源路径、逐要求打勾或其他证据类型。

### 3.4 两类计时器

- MINI 循环：发布前选择 3、4 或 5 分钟；
- 词汇活动：发布前选择 2、3、4 或 5 分钟；
- 到时只提示，不自动关闭、不自动提交；
- 从原生资源返回后，计时状态必须保留。

### 3.5 统一学生端

- 继续使用 `source/in-class/student.html`；
- 教师发布的互动必须出现在统一学生端；
- 不为新课另建学生页面；
- 返回“用”后，房间、当前 MINI、计时器和已有证据不得丢失。

## 4. 课程专属内容：不得被公共框架抹平

以下内容必须依据当课教材单独设计：

- 四个表达任务及其真实交际目标；
- 起点表达、终点表达和终点要求；
- 词汇分层及简明中文释义；
- 每个语法点的例句、归纳、课堂表达和跟进练习；
- 每篇课文的整体选择与细节问答；
- 正式练习、游戏、作业和配图；
- 词汇、语法、课文的课程专属呈现方式。

公共机制负责调用、路由、联动、状态恢复和证据记录；不得为了“统一”而把各课内部教学展示强行改成 L8、L9、L10、L11、L12 或 L13 的外观。

## 5. 当前教学数据契约

### 5.1 词汇

词汇需要同时满足正式课程教学和“用”机制调用。

#### 分层

- `expression`：学生在终点表达中需要主动使用；
- `understanding`：需要理解、认读，但不强制主动产出；
- `context`：服务课文背景或场景理解。

#### 四类活动

1. **认读**
   - 教师一次最多选择 4 个词；
   - 学生端必须收到全部所选词；
   - 使用简单中文解释中文，避免超纲释义。
2. **辨形**
   - 题干或刺激中不得提前出现目标汉字；
   - 使用拼音或非泄题线索；
   - 自动判断。
3. **输入**
   - `promptMode: "meaning"`；
   - `evaluation: "automatic"`；
   - 显式提供 `answer` 与 `acceptedAnswers`。
4. **搭配使用**
   - `promptMode: "open_use"`；
   - `evaluation: "teacher"`；
   - `answer` 放示例答案；
   - 提示学生最多完成 1—2 句话；
   - 提供简短英文说明。

### 5.2 语法

新课默认采用已经验证的渐进式语法数据契约：

`观察例句 → 结构归纳 → 课堂表达 → 跟进练习`

数据至少支持：

- `presentationMode: "progressive_grammar"`；
- 完整例句观察，而不是只显示公式；
- 关键词高亮；
- 结构归纳及必要的结构变体；
- 联系学生生活的课堂表达问题；
- 看图或场景化产出句子的跟进练习；
- 循序渐进的阶段切换。

具体视觉样式和教学处理可因课而异，但不得退回“公式 + 少量例句”的旧版结构。若某语法确实不适合四步结构，必须在内容审计阶段说明原因并获得确认，不能由执行者自行降级。

### 5.3 课文

每篇课文的学生可见教学路径固定为五个阶段：

1. 听 / 读课文
2. 整体选择
3. 细节问答
4. 展示课文
5. 语言与应用

不得另造一套平行的 `flow / gist / details` 页面结构。

#### 整体选择

- 默认每篇 3 题；
- 只检查大意、发展、人物关系或交际目的；
- 题干和选项控制在 HSK3 可理解范围；
- 避免机械反复使用“前面谈什么、后面谈什么”；
- 不能把细节题答案提前泄露给学生。

#### 细节问答

- 默认每篇 5 题；如课程内容确实不足，需在冻结清单中说明；
- 深入检查人物、原因、时间、条件、结果、态度等具体信息；
- 不得与整体题重复；
- 每题应有稳定 ID、题目、拼音、答案、答案拼音、可接受答案和信息点元数据。

#### 语言与应用

需要回连当课真实资源，包括：

- 语法桥接；
- 联系学生个人生活的表达；
- 段落或综合练习；
- 与该 MINI 终点表达有关的支持。

### 5.4 练习资源

- 每个 MINI 只配置一个主要 `linkedResources.practice` 路由；
- 正式资源 ID 放在 `resourceLinks`；
- 页面路由只写公共运行时需要的 `module`、`submodule` 和 `routeState`；
- 必须验证 `routeState` 的题库索引实际指向所声明的正式资源 ID；
- 连词成句、看图表达等必须与当课语法目标匹配，不得随机生成或用无关题目冒充。

### 5.5 升级覆盖层

正式课程 JSON 是课程原始资源，不因“用”升级而覆盖。

- `ready` 资源直接调用；
- `needs_revision` 只在 `resourceOverrides` 中提供升级补丁；
- 覆盖目标 ID 必须真实存在；
- 校验必须确认正式 JSON 哈希未改变。

## 6. 新课建设的七个阶段与停止闸门

任何执行者不得从一句“开始做 L14”直接跳到页面编码。

### 阶段 0：基线核验

**只审计，不设计内容，不改代码。**

必须输出：

1. 当前分支、HEAD 和工作区状态；
2. 最新已上线完整课程及其文件清单；
3. 公共运行时、统一学生端、profile schema、构建器和校验器位置；
4. 旧模板与现行模板的冲突清单；
5. 本课预计复用、课程专属和可能缺失的资源；
6. 明确写出：“`l08-use-pilot.*` 仅为公共运行时，不是 L8 内容模板”。

**闸门：** 基线文件缺失、分支落后或无法确认最新版本时，必须停止并汇报。

### 阶段 1：教材资源审计

**只提取教材事实，不设计页面。**

必须确认：

- 课文数量、文本、人物、体裁和音频；
- 全部生词及教材释义；
- 全部语法点；
- 原教材练习；
- 图片及版权/来源状态；
- 缺失、歧义和无法验证的资源。

**闸门：** 不得凭课程标题或相邻课程推测课文、生词和语法。

### 阶段 2：课程内容蓝图

**设计内容，但不改代码。**

提交：

- 课次 A/B/C 划分；
- 词汇教学分组与场景；
- 渐进式语法四步设计；
- 每篇课文五阶段教学设计；
- 与语法匹配的练习、竞赛、测试和课后任务；
- 每篇课文的 MINI 表达任务草案；
- 正式资源稳定 ID 规划。

**闸门：** 先人工确认蓝图，再进入数据实现。

### 阶段 3：正式课程数据实现

实现正式课程 JSON、构建脚本和正式课程校验器。

要求：

- 构建结果可重复生成且无差异；
- 数据结构从一开始就能被公共“用”机制引用；
- 不把升级配置混入正式课程 JSON；
- 不复制课程专用教师页或学生页；
- 词汇、语法、课文和练习原生教学样式完整可用。

**闸门：** 正式课程校验和原生页面体验通过后，才能冻结课程内容。

### 阶段 4：冻结结构化升级清单

为每个 MINI 明确：

- 表达任务；
- 起点、终点、终点要求、支持卡和响应方式；
- `textId`；
- 词汇、语法、课文和唯一练习路由；
- 正式 `resourceLinks`；
- 整体选择、细节问答和段落练习；
- 词汇三层分级及四类活动；
- `needs_revision` 与覆盖补丁；
- 起点图片；
- 三类证据和两类计时器。

**闸门：** 清单未冻结，不得开始 profile 构建。

### 阶段 5：公共机制接入

优先只增加：

- `scripts/build-hsk3-lXX-use-profile.js`；
- `scripts/validate-hsk3-lXX-use-profile.js`；
- `source/data-model/experiments/HSK3-LXX-USE-PILOT-V1.json`；
- `source/data-model/hsk3-curriculum.js` 中该课配置。

只有 `classpro-use-profile/v3` 确实无法表达冻结内容时，才允许最小修改共享运行时。修改共享代码时：

- 必须按能力设计，不按课号设计；
- 不得出现 `lesson === "HSK3-LXX"`；
- 必须回归验证所有已上线 HSK3 课程。

### 阶段 6：技术与人工验收

自动验证至少包括：

1. 配置可重复生成；
2. 正式资源 ID 全部真实存在；
3. 正式课程 JSON 哈希不变；
4. MINI 与课文、词汇、语法、练习映射正确；
5. 整体题和细节题不重复；
6. 词汇四类活动符合规则；
7. 两类计时器正常；
8. 三类证据可记录和导出；
9. 原生资源返回后状态恢复；
10. 旧版直接入口保留；
11. 已上线课程行为没有改变；
12. 1366×768 和 1920×1080 两种课堂视口无关键遮挡或裁切。

人工体验至少包括：

- 教师端进入课堂、切换 MINI、调用原生资源并返回；
- 统一学生端进入同一房间并接收互动；
- 认读一次发布 4 个词；
- 辨形不泄题；
- 输入题自动判断；
- 搭配题英文说明与两句上限；
- 起点、路径、终点实际产生数据；
- 原生词汇、语法、课文呈现没有被公共框架替换。

#### 6.1 验收职责边界（L16—L18 起执行）

默认按以下分工执行；用户在当轮明确调整时，以用户最新要求为准。

**执行者负责的技术验收：**

1. 教材事实、正式内容与 `teaching_extension` 边界；
2. 构建脚本、正式 JSON、profile、资源路径和课程目录配置；
3. 数据结构是否与共享渲染器实际读取的字段一致，禁止只检查“JSON 中存在字段”；
4. JSON/JavaScript 可解析、稳定 ID、真实资源引用、A/B/C 与 MINI 路由；
5. 正式课和 profile 重复构建幂等；
6. 自动校验、课程开放状态、Git 改动范围和发布分支；
7. 用户批准发布后，提交、推送 `main` 并确认 GitHub Pages 工作流结果；
8. 把本轮发现的结构性问题固化到本文档和校验器，避免只留在对话中。

**用户负责的人工验收：**

1. 教学目标、问题设计、答案与干扰项的内容质量；
2. 教师端与学生端实际连通、课堂发布/接收、MQTT/GAS 数据闭环；
3. 真实设备、投影视口、文字大小、裁切、热点和课堂操作手感；
4. 词汇、语法、课文、练习、竞赛和作业是否适合真实课堂；
5. 是否批准课程开放、提交和上线。

**交接规则：**

- 执行者完成技术验收后，提供改动清单、校验结果和本地地址；
- 用户完成内容与连通性验收并反馈问题；
- 执行者修复代码并补自动校验，用户确认体验结果；
- 用户已经完成并明确批准的内容/连通性测试，发布时不重复执行，除非发布代码又改动了共享运行时或相关内容；
- 共享运行时一旦变更，执行者仍必须完成受影响旧课的技术回归，不能转交给用户代替。

### 阶段 7：发布

只有人工体验明确确认后，才允许：

1. 只暂存本课必需文件；
2. 提交；
3. 推送正确分支；
4. 检查实际部署分支和课程开放状态；
5. 验证线上入口。

如果用户已经完成内容与连通性验收，并明确要求发布阶段不重复测试，则发布阶段只执行构建、静态校验、Git 范围核对、推送和部署状态确认；上线后的课堂内容与连通性复验由用户负责。

不得把“代码已推送”等同于“课程已开放”。课程目录中的 `status`、`openForUse`、`useProfile` 和部署来源必须同时确认。

## 7. 硬性禁止项

新课建设中不得出现：

- 复制 L8、L9、L10、L11、L12 或 L13 的具体表达任务；
- 把 `l08-use-pilot.*` 当作 L8 课程模板；

## 15. L15 首轮问题复盘与 L16—L18 防复发要求

L15 首轮虽然完成了正式 JSON 和 profile，但人工验收暴露出环境判断、渲染契约和练习质量没有在自动校验阶段被充分拦截。L16—L18 必须执行以下规则。

### 15.1 不得误用 Render 或登录模式

L15 开发中一度错误地沿用了历史 Render/教师登录试点思路，而当前正式模式是从 ClassPro 主界面直接进入教师端和学生端，并由 GitHub Pages 发布静态前端。

以后开始新课前必须先检查：

1. 当前 `index.html` 的教师端、学生端真实链接；
2. `source/teacher/index.html` 和 `source/student/entry.html` 的当前直达模式；
3. `.github/workflows/deploy-pages.yml` 的正式发布来源；
4. `origin/main` 的最新提交和实际课程开放状态。

除非用户当轮明确要求，不得：

- 启用 Render；
- 恢复教师登录页；
- 引入账号、密码、私密名单或服务器会话；
- 把历史多班登录试点文档当作当前正式入口规范；
- 仅依据未刷新的本地 `origin/main` 判断线上版本。执行发布前必须先 `git fetch` 并重新核对远端。

### 15.2 语法数据必须按真实渲染契约验收

不能只确认语法内容写进了构建器。必须确认共享页面实际读取的字段完整：

- `grammar.examples` 至少5条真实例句；
- `grammarTeachingNotes.examples` 与正式例句一致；
- `observeHighlights` 与例句对应；
- `visualLearning`、`oralQuestions`、`structureVariants`、`followUp` 完整；
- 每条例句的汉字、拼音、英文和来源标记完整；
- 语法图片、目标表达和示例答案语义一致；
- 不得以通用句、空数组、只存在于说明字段中的内容代替页面实际使用的数据。

校验器必须直接检查共享渲染器所消费的字段，而不是只检查自定义字段名称。

### 15.3 课文“语言与应用”不得为空

L15 首轮把内容写在了共享页面不读取的字段形状中，导致“语言与应用”下面显示为空。以后每篇课文必须同时验证：

- `keyPoints` 是包含 `hanzi`、`pinyin`、`note` 的对象数组；
- `cultureDiscussion` 至少包含 `title`、`questions`、`background`、`wordCards`、`sampleAnswers`；
- `retellScaffold` 至少包含5个 `nodes` 和可直接使用的 `frame`；
- `languageAndApplication` 包含 `grammarIds`、`personalPrompt`、`paragraphPracticeId` 和 MINI 映射；
- 课文个人迁移任务与对应 MINI 终点任务一致；
- 对话、日记等体裁使用共享页面已经支持的布局。

不得把“字段存在”视为“页面有内容”；正式校验器必须检查数组数量、对象键和非空文本。

### 15.4 词汇情景必须提出具体问题

L15 首轮八个词汇场景使用了同一条通用提示，无法体现四篇课文的具体信息。以后每个场景必须有独立的：

- 场景标题；
- 具体问题；
- 观察提示；
- 至少两个参考表达；
- 与图片、热点词和本篇课文一致的信息点。

禁止使用“请根据图片使用目标词介绍场景”一类可替换到任何课程的通用提示作为最终内容。

### 15.5 练习不仅要有数量，还要满足显示契约和内容质量

L15 首轮出现了词卡文字溢出、短文理解缺少短文、问答匹配内容不符合要求、任务转盘无任务等问题。L16—L18 必须执行：

1. `v2_say_guess`：词卡目标使用能完整显示的词语，默认不超过2个汉字；长情境放在任务或提示字段，不放进词卡正面；
2. `r3_independent_reading`：每题必须有标题、完整短文、问题、3个选项和唯一答案；
3. `v7_word_match`：每组5对完整问题与完整回答，不能退化为“词语—释义”匹配；
4. 任务转盘：每项必须有 `challenge`、`scene`、`prompt`、`keywords` 和 `sample`；
5. 任务卡：前四张必须与四个 MINI 的终点任务逐字或语义一致；
6. 所有题目必须检查题干是否自然、答案是否唯一、干扰项是否合理、语言是否符合 HSK3；
7. 禁止保留“正确答案”“干扰项A”“L15短文”“完成口语任务”等占位文本；
8. 正式校验器必须检查渲染器需要的字段、文本长度、数量和非空内容。

### 15.6 课程目录和发布状态

- 开发与本地验收阶段默认保持 `preparing/openForUse:false`；
- 只有用户明确批准开放时，才改为 `ready/openForUse:true`；
- 发布前同时核对 `status`、`openForUse`、`teacherVisible` 和 `useProfile`；
- GitHub Pages 只由 `main` 触发，发布分支推送不等于上线；
- 发布前刷新远端，确认提交真正基于最新的 `origin/main`；
- 若本地存在与远端内容相同但哈希不同的基线提交，只重放本课提交，不重复合并或发布上一课。
