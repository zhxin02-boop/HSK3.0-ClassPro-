# ClassPro HSK3 第14课及后续课程建设工作规范

> 文档状态：现行（Active）  
> 版本：v1.0  
> 生效日期：2026-10-28  
> 适用范围：HSK3-L14 及后续从零建设、旧课升级与公共“用”机制接入  
> 目的：把已经在 L9—L13 验证的课程框架固化为唯一建设基线，避免再次回退到 L8 或更早的旧模板。

---

## 1. 这份规范解决什么问题

L13 从零建设时经历了多次返工。首版沿用了 L8 的模板和呈现方式；补充 L9—L12 材料后，仍然没有一次进入当前框架，直到第三轮调整才达到预期。

这不是单个内容设计错误，而是建设流程存在以下系统性缺口：

1. **没有唯一权威基线。** 最新机制分散在 L9—L12 配置、共享运行时、校验脚本和对话记录中，仓库内没有一份明确声明“当前应按什么建设”的现行文档。
2. **旧文档仍具有误导性。** `HSK3界面模板与执行标准.md` 仍将 L01 写为后续课程默认模板，旧的课程方案也保留早期数据结构。执行者无法判断新旧规则的优先级。
3. **共享文件名称造成锚定偏差。** 公共“用”页面仍叫 `l08-use-pilot.html/js`。这是历史文件名，不代表 L8 是课程内容或教学样式模板，但名称容易让执行者把“共享运行时”误解为“复制 L8”。
4. **“参考 L9—L12”不够精确。** 四课各有课程专属样式，只有部分机制是公共的。把四课笼统交给执行者，容易发生选择性模仿和结构混用。
5. **“正式课程建设”和“用机制接入”被割裂。** 如果先按旧结构完成正式课，再在最后接“用”，会造成语法、课文、练习和资源 ID 无法自然映射，只能返工补结构。
6. **验收标准只有文字，没有前置闸门。** 旧版结构即使能够打开页面，也不会在内容设计阶段失败，问题通常到人工体验时才被发现。
7. **缺少禁止项。** 提示词说明了“要做什么”，却没有明确列出不得出现的旧结构、旧页面和课程专用分支。

因此，今后不能只靠一段长提示词控制结果，而要使用：

**版本化基线 + 分阶段交付 + 每阶段停止确认 + 自动校验 + 人工体验**。

## 2. 权威规则与优先级

发生冲突时，按以下顺序处理：

| 优先级 | 权威来源 | 用途 |
|---|---|---|
| 1 | 本文档 | 决定建设流程、公共机制边界、硬性禁止项和验收闸门 |
| 2 | 当前已上线并已提交的最新完整课程 | 提供实际可运行的结构基线；L13 正式上线并合并后，L14 默认以 L13 为首要基线 |
| 3 | `classpro-hsk3-lesson` 课程建设技能 | 约束具体执行步骤、课程数据质量和浏览器验收 |
| 4 | `classpro-use-profile/v3`、共享运行时及对应校验脚本 | 定义公共“用”、统一学生端、证据、计时器和路由能力 |
| 5 | 当课冻结版结构化清单 | 定义该课专属任务、词汇、语法、课文、练习和资源映射 |
| 6 | L8—L12 旧方案、旧审计文档和历史对话 | 只作历史参考，不得覆盖现行规则 |

### 2.1 找不到基线时的处理

开始新课前，必须在当前分支中确认“最新完整课程”的正式 JSON、构建脚本、校验脚本、升级配置和课程目录状态均存在。

如果 L13 已经上线，但当前工作区或分支中没有 L13：

- 停止课程设计和编码；
- 先说明当前分支落后或工作区不完整；
- 获取正确分支或最新提交；
- 不得静默退回 L12、L8 或 L01 作为模板。

### 2.2 关于 `l08-use-pilot.*`

`source/in-class/l08-use-pilot.html` 和 `source/in-class/l08-use-pilot.js` 是历史命名的**公共运行时**。

- 可以复用其公共能力；
- 不得把其 L8 内容、页面布局细节或课程教学样式当作新课模板；
- 不因新建 L14 而复制 `l14-use.html/js`；
- 不加入 `lesson === "HSK3-L14"` 一类课程专用运行时分支。

## 3. 当前公共框架：必须统一的部分

以下是平台公共机制，不随课程改变。

### 3.1 教师主界面

主界面保持五个入口：

1. 应用
2. 讲授
3. 练习
4. 竞赛
5. 测试

“应用”由共享升级入口注入；正式教师页不得为某一课另造专属“用”页面。

### 3.2 MINI 循环

默认一篇课文对应一个 MINI 循环。若教材实际不是四篇课文，必须先提出差异，不得机械制造四个循环。

每个循环遵循：

`起点表达 → 教师按需调用资源 → 终点表达`

“用”是表达起点和终点，不强迫所有课采用完全相同的内部教学流程。

### 3.3 三类核心证据

只统一记录：

1. `entry_expression`：起点表达；
2. `actual_learning_path`：教师在本 MINI 中实际打开的课堂资源；
3. `exit_expression`：终点表达。

不默认增加逐学生资源路径、逐要求打勾或其他证据类型。

### 3.4 两类计时器

- MINI 循环：发布前选择 3、4 或 5 分钟；
- 词汇活动：发布前选择 2、3、4 或 5 分钟；
- 到时只提示，不自动关闭、不自动提交；
- 从原生资源返回后，计时状态必须保留。

### 3.5 统一学生端

- 继续使用 `source/in-class/student.html`；
- 教师发布的互动必须出现在统一学生端；
- 不为新课另建学生页面；
- 返回“用”后，房间、当前 MINI、计时器和已有证据不得丢失。

## 4. 课程专属内容：不得被公共框架抹平

以下内容必须依据当课教材单独设计：

- 四个表达任务及其真实交际目标；
- 起点表达、终点表达和终点要求；
- 词汇分层及简明中文释义；
- 每个语法点的例句、归纳、课堂表达和跟进练习；
- 每篇课文的整体选择与细节问答；
- 正式练习、游戏、作业和配图；
- 词汇、语法、课文的课程专属呈现方式。

公共机制负责调用、路由、联动、状态恢复和证据记录；不得为了“统一”而把各课内部教学展示强行改成 L8、L9、L10、L11、L12 或 L13 的外观。

## 5. 当前教学数据契约

### 5.1 词汇

词汇需要同时满足正式课程教学和“用”机制调用。

#### 分层

- `expression`：学生在终点表达中需要主动使用；
- `understanding`：需要理解、认读，但不强制主动产出；
- `context`：服务课文背景或场景理解。

#### 四类活动

1. **认读**
   - 教师一次最多选择 4 个词；
   - 学生端必须收到全部所选词；
   - 使用简单中文解释中文，避免超纲释义。
2. **辨形**
   - 题干或刺激中不得提前出现目标汉字；
   - 使用拼音或非泄题线索；
   - 自动判断。
3. **输入**
   - `promptMode: "meaning"`；
   - `evaluation: "automatic"`；
   - 显式提供 `answer` 与 `acceptedAnswers`。
4. **搭配使用**
   - `promptMode: "open_use"`；
   - `evaluation: "teacher"`；
   - `answer` 放示例答案；
   - 提示学生最多完成 1—2 句话；
   - 提供简短英文说明。

### 5.2 语法

新课默认采用已经验证的渐进式语法数据契约：

`观察例句 → 结构归纳 → 课堂表达 → 跟进练习`

数据至少支持：

- `presentationMode: "progressive_grammar"`；
- 完整例句观察，而不是只显示公式；
- 关键词高亮；
- 结构归纳及必要的结构变体；
- 联系学生生活的课堂表达问题；
- 看图或场景化产出句子的跟进练习；
- 循序渐进的阶段切换。

具体视觉样式和教学处理可因课而异，但不得退回“公式 + 少量例句”的旧版结构。若某语法确实不适合四步结构，必须在内容审计阶段说明原因并获得确认，不能由执行者自行降级。

### 5.3 课文

每篇课文的学生可见教学路径固定为五个阶段：

1. 听 / 读课文
2. 整体选择
3. 细节问答
4. 展示课文
5. 语言与应用

不得另造一套平行的 `flow / gist / details` 页面结构。

#### 整体选择

- 默认每篇 3 题；
- 只检查大意、发展、人物关系或交际目的；
- 题干和选项控制在 HSK3 可理解范围；
- 避免机械反复使用“前面谈什么、后面谈什么”；
- 不能把细节题答案提前泄露给学生。

#### 细节问答

- 默认每篇 5 题；如课程内容确实不足，需在冻结清单中说明；
- 深入检查人物、原因、时间、条件、结果、态度等具体信息；
- 不得与整体题重复；
- 每题应有稳定 ID、题目、拼音、答案、答案拼音、可接受答案和信息点元数据。

#### 语言与应用

需要回连当课真实资源，包括：

- 语法桥接；
- 联系学生个人生活的表达；
- 段落或综合练习；
- 与该 MINI 终点表达有关的支持。

### 5.4 练习资源

- 每个 MINI 只配置一个主要 `linkedResources.practice` 路由；
- 正式资源 ID 放在 `resourceLinks`；
- 页面路由只写公共运行时需要的 `module`、`submodule` 和 `routeState`；
- 必须验证 `routeState` 的题库索引实际指向所声明的正式资源 ID；
- 连词成句、看图表达等必须与当课语法目标匹配，不得随机生成或用无关题目冒充。

### 5.5 升级覆盖层

正式课程 JSON 是课程原始资源，不因“用”升级而覆盖。

- `ready` 资源直接调用；
- `needs_revision` 只在 `resourceOverrides` 中提供升级补丁；
- 覆盖目标 ID 必须真实存在；
- 校验必须确认正式 JSON 哈希未改变。

## 6. 新课建设的七个阶段与停止闸门

任何执行者不得从一句“开始做 L14”直接跳到页面编码。

### 阶段 0：基线核验

**只审计，不设计内容，不改代码。**

必须输出：

1. 当前分支、HEAD 和工作区状态；
2. 最新已上线完整课程及其文件清单；
3. 公共运行时、统一学生端、profile schema、构建器和校验器位置；
4. 旧模板与现行模板的冲突清单；
5. 本课预计复用、课程专属和可能缺失的资源；
6. 明确写出：“`l08-use-pilot.*` 仅为公共运行时，不是 L8 内容模板”。

**闸门：** 基线文件缺失、分支落后或无法确认最新版本时，必须停止并汇报。

### 阶段 1：教材资源审计

**只提取教材事实，不设计页面。**

必须确认：

- 课文数量、文本、人物、体裁和音频；
- 全部生词及教材释义；
- 全部语法点；
- 原教材练习；
- 图片及版权/来源状态；
- 缺失、歧义和无法验证的资源。

**闸门：** 不得凭课程标题或相邻课程推测课文、生词和语法。

### 阶段 2：课程内容蓝图

**设计内容，但不改代码。**

提交：

- 课次 A/B/C 划分；
- 词汇教学分组与场景；
- 渐进式语法四步设计；
- 每篇课文五阶段教学设计；
- 与语法匹配的练习、竞赛、测试和课后任务；
- 每篇课文的 MINI 表达任务草案；
- 正式资源稳定 ID 规划。

**闸门：** 先人工确认蓝图，再进入数据实现。

### 阶段 3：正式课程数据实现

实现正式课程 JSON、构建脚本和正式课程校验器。

要求：

- 构建结果可重复生成且无差异；
- 数据结构从一开始就能被公共“用”机制引用；
- 不把升级配置混入正式课程 JSON；
- 不复制课程专用教师页或学生页；
- 词汇、语法、课文和练习原生教学样式完整可用。

**闸门：** 正式课程校验和原生页面体验通过后，才能冻结课程内容。

### 阶段 4：冻结结构化升级清单

为每个 MINI 明确：

- 表达任务；
- 起点、终点、终点要求、支持卡和响应方式；
- `textId`；
- 词汇、语法、课文和唯一练习路由；
- 正式 `resourceLinks`；
- 整体选择、细节问答和段落练习；
- 词汇三层分级及四类活动；
- `needs_revision` 与覆盖补丁；
- 起点图片；
- 三类证据和两类计时器。

**闸门：** 清单未冻结，不得开始 profile 构建。

### 阶段 5：公共机制接入

优先只增加：

- `scripts/build-hsk3-lXX-use-profile.js`；
- `scripts/validate-hsk3-lXX-use-profile.js`；
- `source/data-model/experiments/HSK3-LXX-USE-PILOT-V1.json`；
- `source/data-model/hsk3-curriculum.js` 中该课配置。

只有 `classpro-use-profile/v3` 确实无法表达冻结内容时，才允许最小修改共享运行时。修改共享代码时：

- 必须按能力设计，不按课号设计；
- 不得出现 `lesson === "HSK3-LXX"`；
- 必须回归验证所有已上线 HSK3 课程。

### 阶段 6：技术与人工验收

自动验证至少包括：

1. 配置可重复生成；
2. 正式资源 ID 全部真实存在；
3. 正式课程 JSON 哈希不变；
4. MINI 与课文、词汇、语法、练习映射正确；
5. 整体题和细节题不重复；
6. 词汇四类活动符合规则；
7. 两类计时器正常；
8. 三类证据可记录和导出；
9. 原生资源返回后状态恢复；
10. 旧版直接入口保留；
11. 已上线课程行为没有改变；
12. 1366×768 和 1920×1080 两种课堂视口无关键遮挡或裁切。

人工体验至少包括：

- 教师端进入课堂、切换 MINI、调用原生资源并返回；
- 统一学生端进入同一房间并接收互动；
- 认读一次发布 4 个词；
- 辨形不泄题；
- 输入题自动判断；
- 搭配题英文说明与两句上限；
- 起点、路径、终点实际产生数据；
- 原生词汇、语法、课文呈现没有被公共框架替换。

### 阶段 7：发布

只有人工体验明确确认后，才允许：

1. 只暂存本课必需文件；
2. 提交；
3. 推送正确分支；
4. 检查实际部署分支和课程开放状态；
5. 验证线上入口。

不得把“代码已推送”等同于“课程已开放”。课程目录中的 `status`、`openForUse`、`useProfile` 和部署来源必须同时确认。

## 7. 硬性禁止项

新课建设中不得出现：

- 复制 L8、L9、L10、L11、L12 或 L13 的具体表达任务；
- 把 `l08-use-pilot.*` 当作 L8 课程模板；
- 新建 `l14-use.html/js` 等课程专用公共页面；
- 新建割裂的学生端；
- 在共享运行时加入按课号判断的分支；
- 用随机练习代替真实资源映射；
- 在整体题中提前提供细节题答案；
- 使用大量超纲词或机械“前面/后面”题型；
- 把 `needs_revision` 直接写回正式课程 JSON；
- 未经确认跨越阶段闸门；
- 因当前分支缺少最新课程而自动退回旧模板；
- 清理、覆盖或提交工作区中的无关改动。

## 8. 每课必须维护的文件边界

实际文件以仓库结构为准，典型边界如下：

- `scripts/validate-hsk3-lXX.js`

### 公共运行时层

默认不改。只有公共能力缺失时最小修改：

- `source/in-class/l08-use-pilot.html/js`
- 统一学生端及共享桥接代码
- 公共数据导出与状态恢复代码

一旦修改公共运行时，必须回归所有已上线课程。

## 9. L14 及以后可直接复制的启动提示词

以下提示词用于**阶段 0 和阶段 1**，不要把所有阶段压缩成一次任务。

```text
我要从零开始建设 HSK3 第XX课。请严格执行仓库中的
docs/ClassPro-HSK3-L14及后续课程建设工作规范.md
以及当前 classpro-hsk3-lesson 技能。

本轮只做“基线核验 + 教材资源审计”，不要设计最终课程内容，不要修改代码，不要提交或上线。

开始前必须：

1. 核对当前分支、HEAD 和工作区状态；
```
