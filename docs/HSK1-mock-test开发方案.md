# HSK1 Mock Test 开发方案与数据契约

> 目标：在 ClassPro+ 课中界面新增“测 / Mock Test”板块，用于教师统一组织 HSK1 模拟测试。测试由教师端开放答题和播放音频，学生端只在课堂中进入答题；记录类型单独标记为 `mock_test`，不混入普通课中互动分数。

## 1. 开发顺序

1. 最小可测版本：少量听力题 + 少量阅读题 + 教师开放测试 + 自动计分 + 独立提交记录。
2. 完整 HSK1-mock-01：听力 20 题、阅读 20 题。
3. 教师端测试控制：教师选择测试、开放答题、播放听力、查看测试进度、收卷。
4. 测试报告：学生个人成绩、错题；教师全班统计。
5. 音频正式化：按大题生成音频、人工验收、部署到 GitHub Pages。

## 2. HSK1 题型与题量

听力 20 题：

- 1-5：根据听力选择图片。
- 6-10：根据听力问题选择合适答案。
- 11-15：根据两句对话选择合适图片。
- 16-20：听一个句子，再听问题，选择合适回答。

阅读 20 题：

- 21-25：匹配句子和图片。
- 26-30：匹配问答。
- 31-35：选择合适的词填空。
- 36-40：阅读理解。

## 3. 命题规则

- 词汇来源：优先已学课程词汇，其次 HSK1 目标词汇；未学词原则上不进入 mock test。
- 语法来源：只使用已经讲过的语法结构；扩展结构不得进入全真题。
- 题干必须清楚，答案必须唯一。
- 干扰项要合理，但不能造成多答案。
- 听力文本必须自然、短句为主，语速和停顿符合 HSK1 入门学生。
- 图片题的图片必须直接服务答案，不得出现文字、拼音、水印或明显误导。

### 新版样题对照命题规则（用于 HSK1-mock-02 及后续同型测试）

本规则来自 `mock test/样题` 中的 9 张 HSK（一级）模拟测试样题照片。样题只用于确定题型、题量、版式和难度，不复制原题文本。

听力共 20 题，分 4 部分，每部分 5 题：

- 第 1-5 题：听一个短句，选择正确图片。每题独立呈现 A/B/C 三张图片；学生页图片选项下只显示 A/B/C，不显示汉字、拼音或中文提示。
- 第 6-10 题：听一个问句或短句，选择合适的 A/B/C 词语或短语答案。学生页显示选项文字，可含拼音和汉字；录音中不读选项。
- 第 11-15 题：听两句短对话，从 6 张公共图片 A-F 中选择对应图片。学生页只显示图片字母和作答框；录音中不读图片字母。
- 第 16-20 题：听一个陈述句，再听一个问题，选择 A/B/C 答案。学生页显示选项文字；陈述句和问题只在录音/教师稿中出现。

阅读共 20 题，分 4 部分，每部分 5 题：

- 第 21-25 题：读句子，从 6 张公共图片 A-F 中选择对应图片。图片区含 1 个例题用图和 5 个正式答案图；正式题只写句子和作答框。
- 第 26-30 题：问答匹配。从 A-F 六个回答中选择合适回答，其中 1 个用于例题，5 个用于正式题。
- 第 31-35 题：选词填空。从 A-F 六个词语中选择合适词语，其中 1 个用于例题，5 个用于正式题。题干保留括号或空线，答案唯一。
- 第 36-40 题：阅读理解。每题一段 1-2 句短材料，下面一个理解问题和 A/B/C 三个答案；选项为词语或短语，避免长句。

数据与打印验收要求：

- 第 11-15 题必须共享同一组 A-F 图片选项，不能每题各自出现 A/B/C 三张图。
- 第 21-25 题必须共享同一组 A-F 图片选项，不能每题各自出现 A/B/C 三张图。
- 第 26-30 题必须采用问答匹配版式：问题在左侧，A-F 回答在右侧；不能做成每题独立三选项。
- 第 31-35 题必须采用公共词组选词填空版式：A-F 词语先集中出现在上方，再按句子选填；不能做成每题独立三选项。
- 学生卷听力题不得出现“（听录音作答）”这类占位文字；只保留题号、选项和作答空位。
- TTS 输入稿必须在每题开头读出“第 X 题”，再读题目正文；选项字母和图片字母不读。

难度、范围和质量要求：

- 每套测试必须在标题、`titleCn`、`recordLesson` 或等效字段中标明范围，例如 `HSK1 Mock Test 02（1-12课）`。
- mock-02 的词汇、语法范围为 HSK1 第 1-12 课；mock-03 为 HSK1 第 1-15 课；mock-04 为 HSK1 第 1-13 课。每套题只允许使用本范围内已学词汇、语法和专名。
- 严禁出现超纲词。常见需特别检查的词包括：`除了`、`常`、`舒服`、以及所有超出当前测试范围的后续课程词。
- 听力第 11-15 题不能连续使用同一种结构，例如全部都是“在哪儿 + VP”。允许自然短对话，不必每题都是显性问答，例如“这几天太热了！”“我也觉得是。”
- 听力文本和阅读句子不能机械重复；阅读第 21-25 题不得直接复用听力 1-20 题中已经出现的完整句子。
- 阅读第 21-25 题句子建议 14-18 个汉字左右，避免过短、像词汇识别题；第 31-35 题填空句建议 10 个汉字以上。
- 第 26-30 题问答匹配可以适度增加语境，但问法必须自然；避免“你家有爸爸、妈妈和你吗？”这类生硬问法。
- 第 36-40 题阅读理解的问题角度要有变化，避免连续都问“去哪儿”。可问“没有买什么”“几岁”“怎么了”“是谁的”“想吃什么”等。
- 每个部分的答案分布避免连续单一答案；干扰项必须来自同一语义场或同级词汇，但不能和正确答案同时成立。
- 干扰项要适度提高质量：不能一眼排除，也不能过难到造成多答案；地点、时间、人物、食物、动作类选项应尽量同类相扰。
- 图片资源优先使用已验收课内图片；若没有 L11-L12 专属图片，图片题可使用 L01-L10 已有图片，L11-L12 重点进入听力文字题、阅读填空和阅读理解题。

音频要求：

- 使用 Microsoft Edge TTS，默认声音为 `zh-CN-YunyangNeural` 男声。
- 当前正式语速使用 `--rate=-40%`。
- 每题题号“第 X 题”只读 1 遍；题目内容读 2 遍。
- 同一题两遍内容之间停顿 2 秒；题与题之间停顿 4 秒；对话内部两句之间停顿约 0.8 秒。

## 4. 数据文件

路径建议：

```text
source/data-model/mock-tests/HSK1-mock-01.json
```

页面定位：

```text
source/in-class/teacher.html     教师端新增“测”板块：选择测试、开放答题、播放音频、查看进度与报告
source/in-class/student.html     学生端接收教师开放的 mock_test payload 并答题
source/mock-test/student.html    仅作为早期原型/内部测试页，后续不在学生主页开放
source/mock-test/results.html    可复用为教师报告视图或嵌入教师端
```

产品规则：

- 不在学生主页单独开放 mock test。
- 教师端控制开始、音频播放、结束与提交锁定。
- 学生端只显示当前教师开放的测试。
- 教师端需要全班答题进度、全部答题报告和个人报告。

顶层字段：

```json
{
  "schemaVersion": "mock-test-1.0.0",
  "testId": "HSK1-mock-01",
  "level": "HSK1",
  "title": "HSK1 Mock Test 01",
  "mode": "mock_test",
  "sourcePolicy": "自建题库；样题只作题型参考",
  "audio": [],
  "sections": []
}
```

题目字段：

```json
{
  "id": "L01",
  "number": 1,
  "skill": "listening",
  "part": "L1_picture_choice",
  "prompt": "听录音，选择正确图片。",
  "audioText": "我坐出租车去学校。",
  "question": "",
  "options": [
    {"id": "A", "text": "坐出租车", "image": "..."},
    {"id": "B", "text": "坐飞机", "image": "..."}
  ],
  "answer": "A",
  "points": 1,
  "sourceType": "mock_test",
  "knowledge": ["出租车", "去学校"],
  "status": "draft"
}
```

## 5. 记录字段

每次提交写入一条 `mock_test` 汇总记录；后续可扩展为逐题明细。

```json
{
  "action": "mock_test_submit",
  "recordType": "mock_test",
  "lesson": "HSK1-MOCK-01",
  "testId": "HSK1-mock-01",
  "studentName": "Student",
  "stage": "mock_test",
  "module": "mock_test",
  "score": 6,
  "total": 8,
  "answer": "{\"L01\":\"A\"}",
  "result": "submitted",
  "submittedAt": "ISO time"
}
```

说明：

- `lesson` 使用 `HSK1-MOCK-01`，避免混入普通课程 sheet。
- `stage/module/recordType` 均明确标记 mock test。
- 本地开发写入 `/api/pre-class-record` 的本地记录文件；线上可由 GAS v2 追加到独立 sheet。

## 6. 音频制作

- 首版可以使用浏览器语音合成或教师朗读，只用于流程测试。
- 正式版音频按大题切分，例如 `listening-part-1.mp3`。
- 对话题使用两个人物分行脚本，TTS 时用不同声音生成，再合并。
- 音频上线前检查：普通话、语速、停顿、音量、角色区分、题间间隔。

## 7. 最小可测版本边界

本轮只实现：

- 原型页学生选择姓名；正式课中版改为继承课堂学生身份。
- 加载 `HSK1-mock-01.json`。
- 渲染少量听力和阅读题。
- 自动计分。
- 本地缓存答题进度。
- 提交一条独立 `mock_test` 记录。
- 文档明确“测”应由教师端课中控制开放，不从学生主页单独进入。

本轮暂不实现：

- 严格防作弊锁屏。
- 教师端课中统一开放答题和播放音频的完整闭环。
- 断网续传到 GAS 的完整确认。
- 全班 mock test 数据面板。
