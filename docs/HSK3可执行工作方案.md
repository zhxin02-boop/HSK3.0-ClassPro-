# HSK3 ClassPro/ClassReady 可执行工作方案

依据文件：`HSK3_ClassPro_ClassReady_课程规划与启动方案.docx`

更新时间：2026-08-18

## 1. 执行原则

HSK3 不另起一套系统，而是在现有 HSK1 ClassPro/ClassReady 闭环上升级。执行顺序为：

1. 先搭框架。
2. 再接入 HSK3-L01 样课内容。
3. 用 HSK3-L01 验证课前、课中、课后和报告闭环。
4. 验证通过后，再沉淀为 HSK3 批量制作规范。

本阶段不追求一次性完成全部 HSK3 内容，也不先批量开发复杂功能。第一目标是让系统能够识别 HSK3、加载 HSK3-L01，并跑通一个最小可用的课程闭环。

## 2. 总体目标

搭建 HSK3 的课程框架，使现有系统支持：

- HSK3 课程目录入口。
- HSK3-L01 标准课程数据文件。
- A/B/C 三段课前任务结构。
- 课前任务闯关与轻量词卡。
- 课中模块池：词汇、语法、课文、练习、表达、转述。
- 课后任务：复习、短文理解、表达或写作。
- 学习数据记录与报告字段。

## 3. 阶段一：框架搭建

### 3.1 目标

让系统具备 HSK3 课程的基本识别、入口展示和数据加载能力。

### 3.2 主要工作

1. 建立 HSK3 课程目录元数据。
2. 扩展 lesson 加载规则，使 `HSK3-L01` 能像 `HSK1-L13` 一样被加载。
3. 建立 HSK3 标准课程数据文件位置。
4. 确认学生端和教师端 URL 可以携带 `lesson=HSK3-L01`。
5. 保持 HSK1 现有课程不受影响。

### 3.3 建议文件落点

- `source/data-model/hsk3-curriculum.js`
- `source/data-model/lessons/HSK3-L01.json`
- `source/student/lesson-links.js`
- `source/pre-class/lesson-data-loader.js`
- `source/in-class/lesson-data-loader.js`
- 可能涉及首页或课程目录页的 HSK 级别入口。

### 3.4 验收标准

- 课程目录中能看到 HSK3-L01。
- 学生端能进入 HSK3-L01 的课前、课中、课后入口。
- 教师端能通过 `lesson=HSK3-L01` 加载课程。
- HSK1-L01 至 HSK1-L15 原有入口和数据加载不被破坏。

## 4. 阶段二：HSK3 数据结构草案

### 4.1 目标

在现有标准课 JSON 基础上扩展 HSK3 所需结构，避免每个页面单独写死逻辑。

### 4.2 核心结构

HSK3-L01 数据建议包含以下顶层模块：

```json
{
  "schemaVersion": "1.1.0",
  "meta": {},
  "sessions": [],
  "vocabulary": [],
  "grammar": [],
  "texts": [],
  "previewMissions": [],
  "inClass": {},
  "postClassTasks": {},
  "report": {}
}
```

### 4.3 新增重点字段

`sessions`：定义一课三次课的内容范围。

```json
[
  {
    "id": "A",
    "title": "第一次课",
    "textIds": ["t_hsk3_l01_01"],
    "previewMissionId": "pm_hsk3_l01_a",
    "focus": ["描述人物", "去机场接朋友"]
  }
]
```

`previewMissions`：定义课前 A/B/C 任务闯关。

```json
[
  {
    "id": "pm_hsk3_l01_a",
    "sessionId": "A",
    "title": "去机场接朋友",
    "durationMinutes": "5-8",
    "spoilerPolicy": "只预热主题，不直接复现课文人物关系、冲突和结局",
    "stages": []
  }
]
```

`keywordCards`：在任务中触发的轻量词卡。

```json
{
  "vocabId": "v_hsk3_l01_jie",
  "hanzi": "接",
  "pinyin": "jiē",
  "english": "pick up; meet",
  "example": "我去机场接朋友。"
}
```

### 4.4 验收标准

- HSK3-L01 JSON 能被解析。
- HSK3 新字段不影响 HSK1 旧字段。
- 课前、课中、报告都能通过同一批 `vocabId`、`grammarId`、`textId` 回连数据。

## 5. 阶段三：ClassReady 课前框架

### 5.1 目标

把课前预习从 HSK1 的固定流程升级为 HSK3 的主题任务闯关。

### 5.2 第一轮只实现 A 段

先实现 HSK3-L01 A 段：`去机场接朋友`。

内容来自：

- `docs/HSK3-L01课前预习A段设计草案.md`

### 5.3 A 段结构

1. 故事开场：今天要去机场接一位新朋友。
2. 第一关：看照片，认识新朋友。
3. 第二关：两个人像不像。
4. 第三关：去哪里接朋友。
5. 第四关：到了机场怎么找人。
6. 第五关：见到朋友怎么说。
7. 最终输出：用 1-2 句话介绍要接的人。

### 5.4 功能边界

第一轮只做：

- 任务关卡展示。
- 单选、排序、句子选择。
- 点击关键词打开轻量词卡。
- 保存最终 1-2 句输出。
- 记录每关完成状态。

第一轮不做：

- 复杂动画。
- AI 自动批改。
- 完整徽章体系。
- B/C 段全部交互细节。

### 5.5 验收标准

- 学生 5-8 分钟内可完成 A 段。
- 不提前剧透课文一人物关系和情节。
- 每个关键词都在任务中自然出现。
- 教师端可以看到学生完成情况和最终输出。

## 6. 阶段四：ClassPro 课中模块池

### 6.1 目标

教师端不固定三次课上课顺序，而是提供 HSK3-L01 可组合模块。

### 6.2 模块清单

第一轮 HSK3-L01 应包含：

- 词汇卡：核心义、常用搭配、3-5 个例句。
- 语法讲解：场景、结构、3-5 个例句。
- 课文讲解：原文、拼音、英文、关键词、判断/选择、转述支架。
- 练习池：选词填空、词句匹配、连词成句、段落理解、情景表达。
- 课堂回收：展示课前学生输出，进行表达升级。

### 6.3 HSK3-L01 课中内容范围

A 对应课文一：

- 主题：认人、描述外貌、去机场接朋友。
- 词汇：以为、像、长、身高、米、瘦、接。
- 语法：看起来/看上去。

B 对应课文二、三：

- 主题：行李问题、服务台求助、机场找人。
- 词汇：行李、丢、箱子、号码、好像、重要、着急、护照、服务台、应该、站、中间、短、头发、年轻。
- 语法：疑问代词的非疑问用法、多项定语。

C 对应课文四：

- 主题：到北京后的经历、事件顺序、复述。
- 词汇：发现、不见、带、帮助、照片。
- 输出：复述机场经历，写 40-60 字短段落。

### 6.4 验收标准

- 教师可以自由选择模块，不被系统强制按固定流程上课。
- 课前 A 段输出能在课中被调出使用。
- 课文讲解不只是逐句翻译，有判断、逻辑图和转述支架。
- 练习池包含本课内容和旧内容复现标签。

## 7. 阶段五：课后任务与报告

### 7.1 目标

形成每次课的课后小闭环，并把学生输出带入下一次课。

### 7.2 课后任务结构

每次课后建议包含四层：

1. 词汇复习。
2. 语法复习。
3. 课文理解或转述。
4. 短输出：口头或书面表达。

### 7.3 三次课课后差异

A 课后：

- 描述一个人。
- 用“看起来/像/比……”写 2-3 句话。
- 输出带入 B 段开场。

B 课后：

- 描述一个行李箱或机场里的人。
- 完成一个求助情景表达。
- 输出带入 C 段复述准备。

C 课后：

- 复述李文到北京后的经历。
- 写 40-60 字短文。
- 生成 HSK3-L01 单课学习报告。

### 7.4 报告字段

报告建议记录：

- 完成情况。
- 关键词掌握情况。
- 语法掌握情况。
- 课文理解情况。
- 表达输出情况。
- 错题与错误原因。
- 下一步建议。

### 7.5 验收标准

- 学生能看到自己完成了什么、哪里薄弱、下一步练什么。
- 教师能看到班级共性问题。
- 主观输出可被教师选入下一次课开场。

## 8. 阶段六：HSK3-L01 内容填充

### 8.1 输入材料

- `textbook data/HSK3/L1.txt`
- `docs/HSK3-L01课前预习A段设计草案.md`
- 现有 HSK1 标准课 JSON 示例。

### 8.2 填充顺序

1. 建立 `meta`、`sessions`、`texts`。
2. 填入 `vocabulary` 和轻量 `keywordCards`。
3. 填入 `grammar`。
4. 填入 `previewMissions.A`。
5. 建立 A 段最小题目。
6. 建立课中词汇、语法、课文模块。
7. 建立第一批练习池。
8. 建立课后任务和报告字段。

### 8.3 验收标准

- HSK3-L01 内容完整但不过度扩展。
- 所有练习都有 `targetIds` 或等效知识点标签。
- 课前不剧透，课中能揭示，课后能巩固。

## 9. 第一轮最小可行范围

为了避免范围过大，第一轮只做以下内容：

1. HSK3-L01 课程入口。
2. HSK3-L01 标准数据文件骨架。
3. A 段课前任务闯关。
4. A 段轻量词卡。
5. A 段最终输出保存。
6. 教师端查看 A 段完成情况和输出。

B/C 段、完整课中模块池、课后报告可先保留数据结构和占位说明，等 A 段跑通后继续填充。

## 10. 风险与控制

### 10.1 主要风险

- 一开始就做太多内容，导致框架无法验证。
- 课前任务变成普通 quiz，失去主题任务感。
- 课前提前剧透课文，削弱课中发现感。
- 数据结构过于专用，后续每课都要写特殊代码。
- HSK3 新字段影响 HSK1 已有课程。

### 10.2 控制方式

- 第一轮只以 HSK3-L01 A 段验证。
- 所有新增字段保持可选。
- HSK1 loader 保持兼容。
- 每个任务都必须有明确语言动作。
- 每个练习都必须能回连词汇、语法或能力标签。

## 11. 建议立即执行的下一步

下一步进入框架搭建，按以下顺序执行：

1. 新建 HSK3 课程目录文件。
2. 新建 HSK3-L01 标准 JSON 骨架。
3. 修改 loader，使 `HSK3-L01` 可加载。
4. 把 A 段草案转成 `previewMissions` 数据。
5. 本地打开课前页面验证 A 段是否能展示。

完成后再进入第二轮：补 B/C 段数据、课中模块池和课后任务。
